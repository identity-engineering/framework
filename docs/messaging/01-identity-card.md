# 01 – Identity Card

**Status:** Draft (Phase 1)  
**Extends:** A2A Agent Card (v1.0+)

An **Identity Card** is the discoverable, signed description of an Identity that other Identities can use for Recognition, addressing, and policy decisions.

It deliberately reuses the A2A Agent Card structure so that any A2A-compliant agent can be registered as (or mapped to) an IE Identity with minimal friction.

## Core Fields (inherited / compatible with A2A)

- `name` – human-readable name
- `description`
- `url` – primary endpoint
- `provider` – organization or owner
- `version`
- `capabilities` – streaming, pushNotifications, etc.
- `skills` / task types
- `securitySchemes` + `security`
- `supportsAuthenticatedExtendedCard`

## IE Extensions (required for Identity-Native Messaging)

```json
{
  "ie": {
    "identityId": "did:ie:... or local UUID",
    "scopes": ["personal", "project:xyz", "team:abc", "org:def"],
    "frequencySignature": {
      "preferred": ["async", "task", "signal-only"],
      "resonanceHints": ["vision-aligned", "high-mass"]
    },
    "ownership": {
      "owner": "identityId or human principal",
      "jurisdiction": "local | managed | hybrid",
      "delegationPolicy": "none | limited | full"
    },
    "recognition": {
      "defaultPolicy": "require-signal | allow-payload | deny",
      "allowedSenders": [],
      "blockedSenders": []
    },
    "causalEntropyConstraints": {
      "maxPayloadImpact": "low | medium | high",
      "requireExplicitConsentFor": ["mass-altering", "stem-altering"]
    },
    "surface": {
      "type": "human | agent | hybrid | collective",
      "runtimeHints": ["openclaw", "hermes", "a2a-native", "local"]
    }
  }
}
```

## Rules

1. Every Identity that participates in messaging MUST publish an Identity Card (or have one generated by an adapter).
2. Signed Cards are preferred (A2A signed Agent Card mechanism + IE extensions).
3. Scopes are first-class: an Identity can be addressable under multiple scopes; the sender chooses the scope.
4. Recognition is evaluated before any Payload is accepted.
5. Causal-Entropy constraints are advisory in Phase 1; enforcement becomes mandatory in later phases.

## Mapping from existing runtimes

| Runtime | How the Card is obtained |
|---------|--------------------------|
| Pure A2A agent | Agent Card + IE wrapper / adapter |
| OpenClaw agent | Adapter generates Card from agent config + workspace |
| Hermes agent | Adapter generates Card from runtime metadata |
| Human (via chat surface) | Card generated from user Identity + active scopes |
| Collective | Card represents the emergent Identity; members listed under specialization |
